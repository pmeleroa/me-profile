  - Decisión: señal principal = crecimiento entre turnos. Se marca `context_overflow` cuando, con mensajes nuevos desde la petición anterior y sin compactación ni limpieza entre medias, Δ`prompt_tokens` < 0,1 × Δestimación. Para la primera petición, que no tiene turno anterior, se usa la proporción con la estimación < 0,1 (0,00–0,02 al desbordar con system corto; con un system prompt largo sobreviviría más y podría no detectarse: se declara como límite). Hay margen claro, así que la detección se mantiene como final `context_overflow`, no baja a `warning`. Límites que el post declara: un solo modelo y un solo servidor, un desbordamiento durante la generación no se detecta con esta señal, y la señal se basa en el comportamiento de Ollama de descartar lo más antiguo.
